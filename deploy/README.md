# Фонова робота у Linux

Встанови Python 3.11+, скопіюй / клонуй проєкт у `~/AI-bot`, заповни `.env` за потреби. Для роботи без входу в сесію потрібен systemd user lingering; його вмикає власник машини або адміністратор. Вимкнення чи сон машини все одно зупиняють агент.

```bash
cd ~/AI-bot
python3 -m venv .venv
mkdir -p ~/.config/systemd/user
cp deploy/orbit.service ~/.config/systemd/user/orbit.service
systemctl --user daemon-reload
systemctl --user enable --now orbit
journalctl --user -u orbit -f
```

База сервісу зберігається в `~/.local/state/orbit/orbit.sqlite3`, окремо від типового CLI-запуску. Для backup цієї бази передай `--db ~/.local/state/orbit/orbit.sqlite3`.

Панель доступна лише на `127.0.0.1:8765` машини сервісу. Для віддаленої роботи використовуй свій автентифікований SSH-тунель; не відкривай HTTP у публічну мережу. Зупинка: `systemctl --user stop orbit`.

# Фонова робота у Windows

У Task Scheduler створи задачу під своїм користувачем: програма — повний шлях до `python.exe` 3.11+, аргументи — `-m orbit`, поле **Start in** — папка `AI-bot`. Налаштуй запуск під час входу / старту ОС та автоматичний перезапуск після збою. Не запускай другу задачу для тієї самої БД. Для щогодинної роботи комп’ютер не повинен переходити в сон.

ОС може примусово завершити задачу без SIGTERM; транзакції SQLite захищають локальний стан. При наступному запуску залишені в черзі команди обробляються. Завжди перевіряй KILL / auto та стан ордерів після перезапуску.
