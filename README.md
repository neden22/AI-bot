# ORBIT · Trading Mission Control

Локальний торговий агент у космічному хайтек-стилі: темна панель, помаранчеві та рожеві акценти, ордери, ринковий радар, журнал SQLite, щогодинні звіти та окреме системне ядро.

**Версія 0.1 виконує паперові угоди. Реальних торгових операцій, підключення Walt і доступу до гаманця тут немає.** Ринкові ціни отримуються з публічного Coinbase Exchange API. Для роботи без мережі є окремий явно позначений режим `simulation`. Обидва режими використовують віртуальні $10 000.

## Запуск у Windows / VS Code

Потрібні Python **3.11+** та Git. Сторонніх Python-залежностей немає.

```powershell
git clone https://github.com/neden22/AI-bot.git
cd AI-bot
```

Якщо зміни ще у pull request, перед запуском перейди на гілку розробки:

```powershell
git fetch origin
git switch codex/orbit-agent
```

Відкрий папку у VS Code, відкрий його термінал і виконай:

```powershell
py -3 -m orbit
```

Відкрий **http://127.0.0.1:8765**. Для Linux / macOS команда запуску — `python3 -m orbit`. Зупинка — `Ctrl+C`.

Сервіс одразу збирає ціни та створює звіт поточної UTC-години. Автопілот початково вимкнений. У вкладці **Ордери та журнал** можна створити паперовий ринковий або лімітний ордер. Кнопка автопілота дозволяє стратегії самостійно відкривати й закривати паперові позиції.

### Якщо немає доступу до Coinbase

Використовуй окрему БД, щоб не змішати синтетичні та ринкові дані:

```powershell
$env:ORBIT_DB = "data/simulation.sqlite3"
py -3 -m orbit --feed simulation
```

Linux / macOS:

```bash
ORBIT_DB=data/simulation.sqlite3 python3 -m orbit --feed simulation
```

Щоб повернутися до ринкових даних у PowerShell, виконай `Remove-Item Env:ORBIT_DB`, потім `py -3 -m orbit --feed coinbase`. Після зміни режиму попередній процес потрібно зупинити.

| Системне ядро | Окремі процеси, OS pipes, supervisor, OS lock, SIGINT / SIGTERM, heartbeat |

### Як працює автопілот

SMA 5/20 обчислюються за **послідовними зразками ціни**, які процес збирає приблизно раз на 30 секунд; це не свічки та не історичний бектест. Для визначення нового перетину потрібно 21 зразок, тобто приблизно 10 хвилин безперервного збору. Мережеві затримки можуть подовжити цей час. Розрив між сусідніми зразками понад 90 секунд блокує сигнал до накопичення нової безперервної серії.

Перетин SMA5 вище SMA20 відкриває паперовий long на $250, якщо ризик дозволяє. Зворотний перетин закриває long. SL/TP діють незалежно від паузи автопілота. Прибутковість цієї навчальної стратегії не доведена. LLM не генерує та не виконує торгові команди.

Ціни старші за 90 секунд не можуть використовуватись для виконання. За недоступності джерела немає підміни синтетичними цінами. Equity може відображати останні відомі ціни з явною індикацією їхнього віку.

## Telegram: звіт щогодини

1. Створи власного бота через офіційний `@BotFather` і відкрий діалог із ботом, надіславши `/start`.
2. Визнач ID свого чату через Telegram Bot API `getUpdates`, використовуючи токен лише локально.
3. Скопіюй `.env.example` у `.env`, розкоментуй і заповни:

```dotenv
TELEGRAM_BOT_TOKEN=your-bot-token
TELEGRAM_CHAT_ID=your-chat-id
```

4. Перезапусти ORBIT. У центрі звітів видно `PENDING` або `SENT`.

Без цих параметрів звіти зберігаються локально. Після налаштування Telegram раніше накопичені звіти також надсилатимуться по черзі. Доставка — **at least once**: якщо процес впаде після приймання повідомлення Telegram, але до запису `sent` у БД, повторне повідомлення можливе. Помилка доставки повторюється зі збільшенням інтервалу до 1 години.

**Звіти надсилає процес ORBIT, поки комп’ютер увімкнений і сервіс працює.** Вимкнення, сон ОС або зупинка процесу переривають моніторинг. Пропущені години не відтворюються заднім числом. Для постійної роботи потрібен власний сервер або машина без переходу в сон. Приклад Linux user service: [deploy/orbit.service](deploy/orbit.service).

## Локальний ШІ через Ollama

Встанови Ollama з офіційного сайту, завантаж модель, яку підтримує твій комп’ютер, і вкажи **точну встановлену назву** в `.env`:

```dotenv
OLLAMA_MODEL=your-installed-model
```

Ollama має слухати `127.0.0.1:11434`. ORBIT використовує `/api/chat` без streaming, максимум 500 токенів генерації, таймаут 30 секунд. Модель отримує запитання та знімок паперового рахунку. Вона не отримує Telegram-токен, API-ключі чи інструменти виконання. Недоступна модель → чесно позначений шаблонний огляд. Текст моделі може містити помилки, тому звіряй числа з панеллю.

## Відношення до системного програмування

Тема для курсової:

> **Розроблення багатопроцесного програмного агента моніторингу та паперового виконання торгових операцій із міжпроцесною взаємодією та відмовостійким журналюванням.**

Це система з керованим життєвим циклом процесів, IPC, синхронізацією доступу до даних і збереженням стану після аварії. Панель — клієнт цього ядра.

Дивись [архітектуру та сценарій захисту](docs/SYSTEMS.md). Якщо дисципліна вимагає саме Arduino або C/C++, цей Python-проєкт **сам по собі не виконує таку вимогу**. Варіанти розширення та межі описані в документі.

## Перевірка

```powershell
py -3 -m unittest discover -s tests -v
```

Тести не потребують мережі, Telegram чи Ollama. Вони перевіряють облік коштів, геп на стопі, резерви, stale-data blocking, добовий захист, crash rollback, ідемпотентні команди, CSRF / Host / Origin та відновлення процесу після примусового завершення.

## Дані та конфігурація

| Змінна | Типове значення |
| --- | --- |
| `ORBIT_DB` | `data/orbit.sqlite3` |
| `ORBIT_FEED` | `coinbase` |
| `ORBIT_PORT` | `8765` |
| `OLLAMA_MODEL` | Не задано — шаблонний огляд |
| `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID` | Не задано — звіти локально |

CLI `--feed` / `--port` мають пріоритет над змінними середовища, а наявні змінні середовища — над `.env`. База simulation не може відкриватися з feed coinbase і навпаки.

Резервна копія працюючої SQLite через backup API:

```powershell
py -3 -m orbit.backup --output backups/orbit-backup.sqlite3
```

Копіювати лише `.sqlite3` під час роботи ненадійно через WAL; використовуй backup-команду або зупини сервіс перед копіюванням. Історія зразків обмежена 7 добами, equity — 30 добами. Ордери, події, звіти, діалоги й команди зберігаються без автоматичного видалення. Панель показує останні 100 ордерів і 20 звітів, CSV містить усі ордери.

Секрети, runtime-база та резервні копії виключені з Git. SQLite не шифрується. HTTP слухає **лише loopback** і має перевірки Host, Origin та CSRF. Це персональний застосунок для довіреної локальної машини, без багатокористувацької авторизації. Не публікуй його через відкритий тунель або reverse proxy без окремого шару автентифікації.

## Межі першої версії та наступний етап

- Немає live trading, плеча, ф’ючерсів, опіки над коштами чи збереження seed-фраз.
- Стопи локальні й дискретні, приблизно раз на 30 с; за збою / сну ОС вони не виконуються. Розрахунковий ризик не обмежує фактичний збиток при гепі.
- Паперова модель не моделює глибину стакана, часткове виконання, біржові кроки кількості та ліквідність. Це не оцінка якості реального виконання.
- Supervisor відновлює **завершені** процеси; завислий живий процес показується як stale heartbeat і потребує втручання. Максимум 3 автоматичні перезапуски за хвилину.
- Конфігурація автопілота зберігається після рестарту. KILL і добовий захист також зберігаються.
- Walt MCP зі скриншота ще не підключено. План реальної інтеграції: [docs/LIVE_INTEGRATION.md](docs/LIVE_INTEGRATION.md).
